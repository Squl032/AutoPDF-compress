# PDF 壓縮工具（改良版）

改自 [eason9709/AutoPDF-compress](https://github.com/eason9709/AutoPDF-compress)（原專案 README 聲明為 MIT 授權）。

## 功能

- **壓縮**：設定目標大小（MB），程式自動逼近；也可手動指定 DPI 與 JPEG 品質。逐頁處理，**記憶體用量與頁數無關**，幾百頁的書也不會吃光記憶體
- **效能模式**：偵測 CPU 核心數與可用記憶體，用多個程序平行處理頁面（省資源 / 平衡 / 高速），頁數多時更快
- **無損瘦身（保留文字）**：不轉成圖片，直接改寫 PDF 結構，文字與畫質不變（選用，需要 `pikepdf`，效果因檔案而異，見下方）
- **重頁轉圖片**：只把少數「向量資料過重」的頁面轉成圖片，書籍可再大幅縮小（代價是那些頁面的文字無法選取）
- **合併**：清單內的 PDF 與圖片依序接成一個 PDF，可用 ↑ ↓ 調整順序
- **拆分**：每個 PDF 依「每 N 頁」切成多個檔案（N=1 即每頁一檔）
- **頁碼範圍**：每個 PDF 可單獨指定頁碼，例如 `1-3,5,8-`
- **圖片轉 PDF**：PNG / JPG / WEBP / BMP / TIFF，安裝 `pillow-heif` 後支援 HEIC / HEIF
- **多語言**：有幾個語言檔就有幾種語言可選，exe 也適用（見下方）
- **啟動前環境檢查**：缺少套件時可一鍵自動安裝
- **拖曳**檔案或資料夾進視窗即可加入
- **不需要安裝 Poppler**（改用 pypdfium2）
- 記住上次的輸出資料夾與所有設定；淺色 / 深色 / 跟隨系統外觀

## 執行

```bash
python autopdf.py
```

第一次執行如果缺少套件，會跳出視窗詢問是否自動安裝（需要網路）。也可以手動：

```bash
pip install -r requirements.txt
```

Linux 需另外安裝 tkinter：`sudo apt install python3-tk`（這個無法用 pip 安裝）。

### 環境檢查指令

| 指令                               | 作用                                                           |
| ---------------------------------- | -------------------------------------------------------------- |
| `python autopdf.py --check-env`    | 檢查並列出各套件版本，缺少時詢問是否安裝                       |
| `python autopdf.py --yes`          | 缺少的套件直接安裝，不詢問（也會補裝先前選擇「否」的選用套件） |
| `python autopdf.py --no-env-check` | 略過檢查                                                       |
| `python autopdf.py --list-lang`    | 列出目前實際載入的語言                                         |
| `python autopdf.py --no-dnd`       | 停用拖曳功能（診斷用：判斷介面異常是否與拖曳套件有關）         |
| `python autopdf.py --export-lang`  | 產生 `lang/_template.json` 翻譯範本                            |

- **必要套件**：customtkinter、pypdfium2、pillow。缺少就無法執行。
- **選用套件**：pillow-heif（HEIC 圖片）、tkinterdnd2（拖曳）。如果你選「否」，之後不會再詢問。
- 打包成 exe 之後套件都已內建，不會執行環境檢查。

## 多語言

### 直接執行 .py

程式啟動時掃描程式旁邊的 `lang/`，**每個 `.json` 就是一種語言**，右上角下拉選單的選項數量就是 JSON 檔的數量。切換語言即時生效；第一次啟動依系統語言自動挑選，之後沿用你的選擇。

```
autopdf.py
lang/
  zh_TW.json   ← 檔名 = 語言代碼
  zh_CN.json
  en.json
  ja.json
  _template.json   ← 底線開頭的檔案會被忽略
```

### 打包成 exe 之後

| 情況                                                                 | 結果                                                   |
| -------------------------------------------------------------------- | ------------------------------------------------------ |
| exe 旁邊**沒有** `lang` 資料夾                                       | 使用打包當下內建的**全部語言**（最新版）               |
| exe 旁邊有 `lang` 資料夾，裡面是**內建沒有的語言**（例如 `ko.json`） | **新增**到選單                                         |
| 外部檔與內建**同代碼**（例如舊版 `en.json`）                         | **忽略外部檔**，使用內建的最新版，記錄區會提示         |
| 外部檔與內建同代碼，且 `_meta` 內有 `"override": true`               | 以內建為底，**疊上外部檔寫了的文字**（沒寫的仍用內建） |

所以舊的語言檔不會蓋掉新版；想自訂某個內建語言的措辭，在檔案裡加上 `override` 並只寫要改的那幾行即可：

```json
{
  "_meta": { "name": "English", "override": true },
  "strings": { "btn.start": "Go!" }
}
```

### 新增一種語言

1. 執行 `python autopdf.py --export-lang` 產生 `lang/_template.json`（含所有可翻譯的文字）。
2. 複製一份，改檔名為語言代碼，例如 `ko.json`。
3. 修改 `_meta.name`（選單顯示的名稱）與 `strings` 裡的文字，存成 UTF-8。
4. 重新開啟程式，選單就會多出該語言。

```json
{
  "_meta": { "name": "한국어", "font": "" },
  "strings": { "btn.start": "변환 시작", "btn.cancel": "취소" }
}
```

- 沒翻譯到的鍵會顯示內建的繁體中文，所以可以先翻一部分。
- `{n}`、`{size}` 這類 `{}` 占位符要原樣保留。
- `_meta.font` 選填，可指定該語言專用的字型。
- 標籤太長會被切掉，翻譯請盡量簡短。
- 壞掉的 JSON 會被略過，並在記錄區顯示原因。
- 語言代碼要用底線格式（`zh_CN`，不是 `zh-cn`），系統語言自動偵測才對得上。

## 打包成 exe

```bash
python build_exe.py
```

這支腳本會：檢查環境（缺套件可自動安裝）→ 安裝 PyInstaller（如果沒有）→ 把 `lang/` 裡**所有語言檔打包進 exe** → 產出 `dist/autopdf.exe`。

| 選項        | 作用                                          |
| ----------- | --------------------------------------------- |
| `--console` | 保留主控台視窗（除錯用，才看得到 print 輸出） |
| `--onedir`  | 資料夾版，啟動較快，但要整個資料夾一起發佈    |
| `--yes`     | 缺套件直接安裝，不詢問                        |

專案資料夾放一個 `icon.ico`，打包時會自動套用為圖示。

每次改了語言檔後重新執行 `python build_exe.py`，新的 exe 就會內建最新的語言。

## 自動壓縮怎麼運作

1. 先保畫質：從原解析度與高品質開始，用二分搜尋找出「剛好不超過目標」的最高 JPEG 品質。
2. 品質壓不下去，才依序降低解析度（最低 72 DPI）。
3. 開啟「**優先達成目標大小**」（預設開啟）時，若仍達不到，會繼續降到更低的解析度與品質，最後自動轉灰階。畫質會明顯變差，記錄區會提醒；關閉這個開關則保留最低畫質，達不到就如實告知。
4. 頁數很多時（約 20～40 頁以上）改用「抽樣估算」：先抽幾頁算出設定，逐頁處理後驗證實際大小，不準會自動修正重試（最多 4 次）。
5. 原檔本來就小於目標大小時，直接複製，不重新壓縮。

目標大小太小會讓內容無法閱讀。例如 800 多頁的書壓到 4 MB 等於每頁只有約 5 KB。這種情況建議改用「拆分頁面」，每份各自壓到合理大小。

## 無損瘦身與重頁轉圖片

需要選用套件 `pikepdf`（`pip install pikepdf`，打包版 exe 已內建）。

**無損瘦身（保留文字）**：不把頁面轉成圖片，直接改寫 PDF，移除多餘的中繼資料（XMP）並重新壓縮。文字、向量、畫質完全不變，文字仍可選取搜尋。

效果**因檔案而異**。實測 8 份書籍（5～218 MB）：

| 省下的比例 | 檔案數 | 說明 |
| --- | --- | --- |
| 0 %～2 % | 4 份 | 原檔本來就很精簡，幾乎沒變（瘦身後沒變小會保留原檔） |
| 9 % | 1 份 | |
| 27 %～33 % | 2 份 | |
| 65 % | 1 份 | 每個物件都附一份中繼資料的出版社書籍 |

**重頁轉圖片**（預設開啟，需先開無損瘦身）：把「向量資料比轉成圖片還大」的頁面（多為複雜圖形）轉成 110 dpi 圖片，其餘頁面維持向量原樣。同樣 8 份書籍，合計可省 **42 %～75 %**。

- 代價：被轉換的頁面文字無法選取、連結消失。圖片多的書籍轉換比例較高，實測約 5 %～37 % 的頁面（例如 chemistry-2e 轉了 440 / 1203 頁、植物學 303 / 829 頁）。
- 一般檢視大小下幾乎看不出差別，放大到很大時文字邊緣會略軟。
- 目標大小做不到時，不會自動改轉圖片（那會讓文字變像素），只會在記錄區提示；想更小請關閉無損瘦身，改用一般壓縮。
- 只適用於 PDF；清單中混入圖片時，該次工作改用一般壓縮。

## 效能模式

PDF 渲染引擎無法多執行緒，所以多核心電腦預設只用到一個核心。「效能模式」會依**核心數**和**目前可用記憶體**決定同時開幾個處理程序：

| 模式         | 最多處理程序數          | 記憶體使用             |
| ------------ | ----------------------- | ---------------------- |
| 省資源       | 1（不平行）             | 最少                   |
| 平衡（預設） | 核心數的一半，最多 4 個 | 不超過可用記憶體的 25% |
| 高速         | 核心數 − 1，最多 16 個  | 不超過可用記憶體的 60% |

- 每個處理程序約需 450 MB 記憶體。介面會顯示偵測到的核心數、記憶體與此模式實際會開幾個。
- 頁數少於 12 頁不會啟動多程序（啟動要約 1 秒，不划算）。
- 多程序出問題（例如被防毒軟體擋下）會自動退回單程序，結果完全相同。
- 這個模式加速的是「頁數多」的文件；單一小檔案不會變快。

## 命令列模式

```bash
python autopdf.py --compress 輸入.pdf 輸出.pdf --target-mb 4 --workers 4
python autopdf.py --compress 輸入.pdf 輸出.pdf --slim            # 無損瘦身
python autopdf.py --compress 輸入.pdf 輸出.pdf --slim --heavy --workers 8   # 再加重頁轉圖片
```

## 頁碼範圍格式

| 輸入     | 意義                              |
| -------- | --------------------------------- |
| （留空） | 全部頁面                          |
| `1-3,5`  | 第 1、2、3、5 頁                  |
| `8-`     | 第 8 頁到最後一頁                 |
| `5,1-2`  | 依輸入順序：第 5 頁，再第 1、2 頁 |

## 注意

- 輸出是「圖片式 PDF」，原本可選取、搜尋的文字會消失。
- 有密碼保護的 PDF 需先解除密碼。
